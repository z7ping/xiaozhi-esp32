# LCD Wiki ES3C28P 2.8 寸 ESP32-S3 智能显示模块

## 待机仪表盘

设备空闲时显示时钟、日期、天气、空气质量、农历、节气、节日和每日宜忌；支持日间、夜间及自动主题。天气和黄历功能需要配置相应的 API Key。联网后也可以通过语音设置天气密钥、黄历密钥和城市。

## 固件烧录后的配置说明

### 固件烧录后有两个 APPKEY 需要配置一下：

- **一个是万年历相关数据获取需要配置**：

万年历相关数据我们使用的是聚合数据的接口，可以自行去网站上去注册获取，免费会员每天有 50 次的请求机会；我们程序中已经做了缓存处理，不重复开关机的情况下，万年历每天只需要调用一次
聚合数据网址：[https://www.juhe.cn/docs/api/id/177](https://www.juhe.cn/docs/api/id/177)
注册成功后需要进行实名认证，然后添加 万年历 的 API 接口，这里面有一个 APPKEY

- **还有一个天气数据获取配置**：

天气数据我们使用的是和风天气的接口；同样你只需要提供一个 AppKey 配置一下就可以使用了；
和风天气的网址：[https://dev.qweather.com/](https://dev.qweather.com/)

和风天气注册好后在控制台里需要创建项目，然后在项目里再创建凭证；就可以拿到 APPKEY

### 拿到两个 APPKEY 后使用鹿戴马平台的 NVS读写工具 进行配置

一、打开：[ESP NVS 在线读取与修改](https://www.16302.com/nvsreadwrite)

1、连接设备；
2、读取 nvs;

二、找到对应的键值更新并写入设备中；

1、万年历的配置键是：

| 命名空间 | 键 | 值 |
| ------------------------------------ | -------------------------------------- | ------ |
| almanac | juhe\_key | 这里的值初始是空的，点后面“编辑”更新 |

2、和风天气的配置键是：

| 命名空间 | 键 | 值 |
| ------------------------------------ | -------------------------------------- | ------ |
| weather | qweather\_key | 这里的值初始是空的，点后面“编辑”更新 |

找到 NVS 空对应的键，把上面获取到的 APPKEY  填入，并再次烧写进芯片中；然后重启设备，如果配置正确就能看到获取到的当地的天气数据和万年历数据。

## 新旧服务端兼容（媒体能力协商）

固件与服务端使用已有 `hello.features.media_control` 做一次握手协商，不新增探测连接或后台任务：

- **新 Go 服务端**：握手响应显式返回 `"features":{"media_control":true}`，固件才允许从触摸播放器发送 `media` 类型的状态查询、列表与控制命令
- **旧版 Go/Python 服务端**：握手缺少字段、字段为 `false`、或握手失败时，一律视为不支持，**不再向服务端发送任何 `media` 命令**，避免旧服务端每 5 秒打印未知消息错误
- 不支持时，触摸播放器显示“服务端未声明触摸播放控制”，播放/切歌/列表/Seek 按钮禁用；传统语音对话和服务端已有 Jellyfin 语音播放能力不受影响
- WebSocket/MQTT 的 hello 都支持；断开、关闭音频通道、重连后自动重新协商，页面每 5 秒刷新可用状态，无需手动切换配置
- 播放控制仍需要已建立的服务端音频会话；**尚未握手或未连接时也不允许发送媒体控制**。普通屏幕/时钟/亮度/万年历功能不依赖此能力

手工验证：旧版服务端连接后反复进入播放器 1 分钟，确认无 `未知消息类型: media` 日志；升级到支持能力声明的服务端并重连，确认触摸播放器自动启用；断线或切回旧版再连接，确认禁用态恢复。

## 横屏触摸 UI（开发中）

基于现有 LVGL 9，当前横屏构建新增轻量触摸页面，**不修改已确认的 V2.4 HTML 交互原型**：

- **首页**：展示系统时间、已有天气与农历快照；复用原像素机器人 LVGL 对象，点击人物发起现有语音对话。
- **页面跳转**：顶部设置按钮、底部故事/儿歌/万年历入口、子页面返回；页面内容按需创建，离开后释放。
- **设置**：亮度滑杆调用板载 PWM 背光，音量滑杆调用现有音频编解码器；松手后持久化。新增儿童模式（隐藏播放器停止按钮，降低误触风险）和暮光配色，使用已有 Settings/NVS 保存。
- **万年历**：支持翻月、选日、返回今天和详情弹层。今天使用现有缓存；其他日期仅在打开详情时通过同一个 AlmanacService 任务调用聚合数据日历日接口，单槽结果缓存，不新增任务，不在翻月时请求。请求失败/额度耗尽明确显示，不能虚构黄历。
- **播放器**：通过现有设备控制通道查询状态、暂停/继续、停止、上/下一首；支持 6 首/页的服务端队列、翻页、点选歌曲。Seek 在 Go 服务端重启曲目并跳过目标之前的解码帧，ESP32 不解码或下载音频；**仅在真实总时长可获得时启用进度滑杆**，未知时显示 --:-- 并禁用拖动。长音频 Seek 可能有明显等待，超出曲目结尾返回错误。需同时运行 Go 服务端 `feat/es3c28p-media-control` 分支。
- 对话、天气、黄历、唤醒词和 Jellyfin 原音频链路仍沿用已有实现；像素横屏版不再创建未使用的旧仪表盘 LVGL 对象与定时器，以减少常驻内存。
- 使用已有 Material Symbols 图标字体，不新增图标库；复用一个机器人对象，不额外创建机器人副本。

## 资源基线测试（诊断构建）

默认的横屏固件不启用资源采样。只有资源诊断构建会每 3 秒在现有 LVGL 任务中输出一条 `ES3C28P_RES` 日志，不增加后台任务，不改变音频协议或屏幕行为。

```bash
# 需要先配置 ESP-IDF v6.0.1+ 环境
python3 scripts/build.py lcdwiki-es3c28p --name lcdwiki-es3c28p-landscape-diag
```

可以保存 USB 串口日志（例如 `idf.py monitor | tee es3c28p.log`，或使用其他串口终端），再生成分状态报告：

```bash
python3 scripts/es3c28p_resource_report.py es3c28p.log
python3 -m unittest discover -s scripts/tests -p 'test_es3c28p_resource_report.py' -v
```

日志字段：`state`（设备状态）、`internal_free/internal_min/internal_largest`（内部 8 位 RAM）、`psram_free/psram_min/psram_largest`（外部 8 位 PSRAM），单位均为字节。`*_min` 是启动以来的最低空闲量，非当前状态瞬时值；`*_largest` 为当前最大连续可分配块。

真机测试顺序：冷启动稳定待机 1 分钟 → 触摸/屏幕切换 → 唤醒并连续对话 → 播放 Jellyfin 故事或儿歌并尝试打断 → 切换天气及黄历数据 → 再次待机。记录各阶段采样与音频异常；对比上一个阶段的最大连续块和历史最低空闲量。完整 UI 与多媒体并发上线之前，必须先取得这组真机数据。

**限制**：这个构建仅用于测量；当前尚未获得实际设备的 RAM 峰值，不能凭静态配置推断可用余量。采样日志不会上传到云端；请保留本地串口记录并核对触摸方向、音频及 Wi-Fi 是否正常。测量后请刷回普通的 `lcdwiki-es3c28p-landscape` 固件。

## 与 ES3C35P 的差异

同厂商的 3.5 寸模块 (`lcdwiki-es3c35p`) 使用 ST77922 QSPI 触显一体屏, 引脚分配完全不同,
因此两者是独立的板子定义, 不可混用固件。

| 项目 | ES3C28P (2.8") | ES3C35P (3.5") |
|------|----------------|----------------|
| 分辨率 | 240×320 | 320×480 |
| 驱动 IC | ILI9341V | ST77922 |
| 显示总线 | 4-Line SPI | QSPI |
| 触摸 IC | FT6336G (0x38) | ST77922 内置 (0x55) |
| I2C 引脚 | SDA=IO16, SCL=IO15 | SDA=IO38, SCL=IO39 |
| 音频 MCLK/BCLK/WS | IO4 / IO5 / IO7 | IO17 / IO18 / IO21 |
| RGB LED | IO42 | IO40 |
| 背光 | IO45 | IO41 |
